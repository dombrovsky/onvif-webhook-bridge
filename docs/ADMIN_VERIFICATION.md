## Delivered scope and preserved contracts

`Web/{AdminAuthentication,ApiEndpoints,ApiModels,JsonContext}.cs` provides opaque server-side sessions, bounded login work/storage, same-origin login, authenticated CRUD/status/event/test routes, CSRF checks for all mutations/tests, explicit secret edit DTOs, masked views and fixed validation/conflict/storage errors. Source-generated System.Text.Json metadata covers every request/response type; unknown properties, missing required constructor fields and non-nullable nulls are rejected. Bodies are bounded to 256 KiB, depth 64 and ten seconds of read time, including bodies without Content-Length. JSON retains default HTML-sensitive escaping; no browser UI or HTML event rendering is added.

The production executable initializes storage and applies administrator bootstrap before starting hosted services. It exits 1 without an established administrator, without starting HTTP listeners, workers or dispatcher. Setup uses `ONVIF_ADMIN_USERNAME` with either `ONVIF_ADMIN_PASSWORD` or bounded UTF-8 `ONVIF_ADMIN_PASSWORD_FILE`. Normal startup ignores bootstrap variables after setup, even stale/unavailable file settings. Only the explicit offline `--reset-administrator` command replaces the stored hash and exits before starting services. It preserves configuration/revision. [ADMINISTRATION.md](ADMINISTRATION.md) documents setup, reset, restart, HTTP/session/CSRF contracts, API fields, limits and errors; [DATA_STORAGE.md](DATA_STORAGE.md) remains the ownership/backup contract.

The store retains its existing PBKDF2-HMAC-SHA256 format, 600,000 iterations, random 16-byte salt and 32-byte hash. Verification does adaptive work for unknown usernames too and compares hash bytes in constant time. No plaintext administrator password is persisted or returned. Reset and setup commit through the store, with storage permission checks before commit; reset clears the calling instance's sessions only after a successful commit. Reset is an offline operator action: a second process cannot revoke the live process's memory, so the documented policy requires stopping the bridge first.

Sessions use independent 256-bit random session/CSRF tokens, expire absolutely after eight hours and are held only in memory, at most 64. Expired capacity is reclaimed, full capacity rejects login, and logout/restart revokes tokens. Cookies are host-only, Path `/`, HttpOnly, SameSite=Strict and Secure for an HTTPS request. Login has five attempts per direct peer and 20 globally per minute, at most 256 peer buckets, and two concurrent adaptive verifications. No forwarded-header/client-address trust or cross-origin CORS access is enabled. Same-origin validation compares normalized scheme/host/port and rejects cross-site/same-site Fetch Metadata. Production HTTPS/proxy deployment remains phase 8; TLS termination at a proxy does not automatically make backend requests HTTPS.

Camera/rule upserts, deletions and enable/disable edits use `ConfigurationStore.Read/Save` with expected revisions and explicit preserve/replace/clear secrets. A failed commit/conflict changes neither active snapshots nor durable configuration. Referenced-camera deletion returns a fixed 409. No API serializes internal stored rows, active camera snapshots, action URLs/headers/bodies, credentials or administrator hashes. Reads use the existing masked store views, bounded inspector history and safe camera/execution statuses. Connectivity tests use the configured camera's existing bounded GetServices path (four concurrent, ten-second operation deadline), with a fixed result separate from subscription readiness. Manual HTTP testing is explicit, authenticated, same-origin and CSRF-protected; it calls the existing bounded dispatcher and returns admission status, never a response body.

`CameraPipeline`, `CameraSupervisor`, `CameraSubscriptionWorker`, matching/cooldown/queue/retry/revision checks, inspector admission, cleanup-before-replacement, recovery cleanup retry and the shared WS-Addressing renewal adapter remain in use. No matcher, cooldown, queue or lease/recovery algorithm was replaced. The unchanged self-origin action predicate is reused for rejecting known self-target camera edits. Camera endpoint validation rejects fragments/known forbidden hosts. The reviewed pinned `OnvifClientSettings.Transport` seam now applies the existing DNS-checked HTTP handler to discovery/pull/cleanup and the independent renewal client: checked-address connection, no metadata/link-local/unspecified/multicast destinations, no redirects/proxies/cookie sharing, ordinary TLS validation, private addresses allowed. Version-matched settings copy and handler ownership/disposal were source-reviewed; existing simulator renewal/recovery/cleanup gates pass with this transport. DNS aliases of the application remain an identification limitation, not a universal self-target guarantee.
