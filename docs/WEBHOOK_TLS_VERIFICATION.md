# Per-webhook certificate validation option

Explicitly authorized follow-up to the completed implementation plan. The rule editor and authenticated API expose `ignoreCertificateValidation`, default false. Existing rules migrate from schema 2 to 3 with validation enabled. The option is public configuration, never a secret replacement operation. PUT replaces it like other public fields; enable/disable and camera edits preserve it.

The dispatcher chooses one of two named HttpClientFactory pools from the immutable action snapshot. Only the opt-in pool accepts invalid certificates; the strict pool and camera handlers retain ordinary validation. Both pools disable redirects, cookies, proxies and request logging, retain checked DNS/address restrictions, and use the existing deadlines, retry policy and revision checks. Changing this option invalidates queued jobs. No global TLS callback is installed.

`WebhookTlsPath` uses a real ephemeral local HTTPS recorder with a self-signed, expired, mismatched certificate. It checks strict failure, opted-in acceptance, strict failure again, strict camera transport, persistence, and invalidation before sending an obsolete job. Windows fixture certificates are reimported from an in-memory PFX for Schannel server-key compatibility. No private certificate material enters the repository.
