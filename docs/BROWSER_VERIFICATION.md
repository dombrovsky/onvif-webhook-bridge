## Delivered scope and unchanged contracts

`wwwroot/{index.html,app.css,app.js}` delivers plain login/logout and authenticated Cameras, Events and Rules screens. No frontend framework, package manifest, Node build, bundler or additional application service is added. `Web/BrowserAssets.cs` serves three explicitly allowlisted embedded resources independently of the current working directory, including in the published NativeAOT executable. Only the empty login shell and its fixed code/styles are public; all configuration/event/status/test reads and mutations retain phase 6 session protection. The sole anonymous API read remains `/health`.

Cameras supports CRUD, enable/disable, bounded saved-camera connectivity testing and independent subscription status/contact/event feedback. Rules supports CRUD, enable/disable, explicit confirmed manual saved-action tests, occurrence/transition, exact/boolean conditions, cooldown, GET/POST, headers/literal body and zero to two additional attempts. Current and last-completed execution results show safe category, attempts, HTTP status and timing. Confirmation distinguishes real action requests, queue acceptance, transport acceptance and destination effects.

Events displays all bounded retained notifications without filtering false, unmatched, initialization or deletion observations. Detailed inspection displays the full retained JSON, including exact matching topic, namespace/dialect information, Source/Data/Key collections, duplicates, ElementItems, extensions, raw message previews, diagnostics and truncation. Topic-only and selected observed scalar Source/Data drafts require review and always save disabled. Truncated observations cannot establish an exact draft. The UI assumes no vendor topic or boolean field name.

Every masked secret input explicitly chooses Preserve/Replace/Clear; required URLs offer Preserve/Replace because clearing is invalid. No stored credential/action value is read back. Editors retain their opening configuration revision. Conflicts preserve the draft for review and require cancel/refresh/reopen/resubmit; mutations are never automatically retried. Validation/session expiry/network failures and disconnected camera status have fixed understandable feedback. Replacement inputs clear when leaving Replace, cancelling, closing or logging out.

Polling performs five bounded reads sequentially with a twelve-second cycle deadline and a three-second delay after completion. Refresh cancels/supersedes the old cycle. Poll IDs prevent an earlier cycle scheduling a competing loop; session generations prevent late data restoring a logged-out screen. Logout stops/aborts polling immediately, revokes through the protected API and clears retained UI data and editors. Failed logout confirmation still clears local state and explicitly identifies the outstanding server-session uncertainty. Session expiry works through both absolute client timeout and server 401; restart invalidates sessions and restores durable configuration without transient history/status/queue state.

Dynamic content uses textContent/form values, with no HTML parsing sink, dynamic links, script evaluation or inline handler markup. CSP allows only same-origin scripts/styles/connections, forbids inline scripts, base URLs and foreign form submissions, and blocks framing. Source-generated API JSON, HTML-sensitive escaping, HttpOnly/SameSite cookies, CSRF and same-origin checks remain intact. No API data/edit DTO or matching/dispatch/persistence behavior changed. Every persistent UI mutation uses the existing API's `ConfigurationStore.Save` before active snapshots change. Matching, cooldown, queue/retry bounds, revision checks, inspector admission, worker reconciliation, cleanup-before-replacement, recovery cleanup retry and WS-Addressing renewal are preserved.

[Browser usage](BROWSER_ADMINISTRATION.md) explains the screens, secrets, conflicts, connection status, polling, sessions and manual-test semantics. README, administration/storage documentation and planning status now reference phase 7. Phase 8 deployment/Compose/workflows/image publication/TaskFlow remain unimplemented and unauthorized.
