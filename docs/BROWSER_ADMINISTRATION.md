# Browser administration

Complete administrator bootstrap first as described in [ADMINISTRATION.md](ADMINISTRATION.md), start the application, then open its root URL. The login shell and its two fixed assets contain no configuration and are available before login. Cameras, Events and Rules load data only after a valid session. The same process serves the embedded HTML/CSS/JavaScript; there is no frontend build or additional service.

## Cameras

Add a name and device-service URL, choose whether to enable, and explicitly replace credentials if needed. Disabled cameras remain saved. Edit preserves credentials unless you select another operation. Enable/disable reconciles the existing independent worker; referenced cameras cannot be deleted until their rules are removed. Status shows subscription state, last contact/event and failure count. A disconnected camera does not disconnect the administration screen or other cameras. Test connectivity makes a bounded service request to the saved endpoint; reachable does not establish subscription readiness or a working activation/reset mapping.

## Events and reviewed drafts

Events shows every retained notification, including false/unmatched/Initialized/Deleted observations. Retention is at most 100 events globally within the existing 1 MiB history budget; each event has existing field/XML/byte bounds. Inspect displays the complete retained JSON as inert text, including topic/dialect/namespace context, timestamps, duplicate Source/Data/Key fields, structured ElementItems, extensions, diagnostics and truncation flags. Serialized XML is the library-exposed subtree, not full original SOAP wire content.

Choose a topic-only draft or a specific observed scalar Source/Data value. The editor preserves the exact matching topic and selected field/value, requires review of camera/condition/action, and always saves new rules disabled. Truncated observations cannot create drafts because clipped data cannot safely define exact matching. If the observed camera was deleted, select a retained camera deliberately before saving. No topic or field name is assumed by the application.

## Rules, secrets and explicit tests

Rules exposes exact topic/field matching, Text versus Boolean comparison, Occurrence versus Transition, cooldown seconds, GET/POST, literal JSON body, custom headers, and zero to two additional attempts. Boolean uses only true/1 and false/0; Transition requires a condition and a known nonmatching-to-matching change. First observations establish a baseline. Retrying may duplicate effects; the default is zero retries. See [matching/delivery contracts](HTTP_VERIFICATION.md) for full behavior. Verify real activation/reset cycles and identity privately before enabling a real transition mapping.

Camera credentials and action URL/headers/body show presence only. Every secret field offers Preserve or Replace; optional fields also offer Clear. Preserve leaves the stored value intact, Replace requires a new value, and Clear removes it. Replacement inputs are blank and discarded when switching away from Replace or closing the editor. Clear both camera username and password for unauthenticated cameras. A required action URL cannot be cleared: replace it or delete the rule. Header replacement uses an array of name/value objects, for example `[{"name":"X-Example","value":"<synthetic-value>"}]`. Body replacement requires literal valid JSON for POST. Changing POST to GET with a stored body requires explicitly clearing the body.

Manual HTTP test asks for confirmation before sending the **saved** action, even for a disabled rule. Its camera must be enabled. This bypasses matching/cooldown and uses the existing bounded dispatcher, deadlines, revision checks and retry settings. Queue acceptance is separate from execution. Current and last-completed results show safe category, attempts, HTTP status, timestamp and duration. A successful HTTP response proves transport acceptance only, not a destination-side action. Verification uses only a local recorder.

## Conflicts, refresh and sessions

Editors retain their opening revision. If another edit commits, Save reports a conflict and keeps the draft for review; cancel, refresh, reopen and resubmit deliberately. There is no automatic overwrite or retry of mutations. Invalid requests show a fixed validation message; field-condition/transition and malformed header-JSON mistakes also have focused browser feedback. Failed storage commits leave the previous configuration active. Unknown request outcomes after a network loss require refreshing/reviewing before resubmission; do not blindly repeat an external test.

A single polling cycle requests configuration/status/events/executions sequentially, with a twelve-second cycle deadline and a three-second delay after completion. Refresh now supersedes a pending cycle; generations prevent obsolete responses scheduling another loop or restoring logged-out data. A failed cycle shows stale/disconnected feedback and retries. Polling pauses automatically when the session expires or is rejected. Logout cancels pending polling immediately, clears screen/editor/event/secret state, revokes the session through the protected API and never restarts polling. If logout cannot be confirmed, the screen explains that the server session may still exist; sign in and retry revocation. Sessions expire absolutely after eight hours; reload recovers a valid session through the protected session API, while application restart invalidates it. Runtime events, statuses and queues are not restored.

All network data is assigned through textContent or form values, never parsed as markup, HTML links or scripts. CSP permits only same-origin scripts/styles/connections and blocks inline scripts, framing, base URLs and foreign form submissions. API JSON source generation, cookie, CSRF/origin validation and transaction-before-snapshot contracts remain unchanged. Use HTTPS beyond controlled local development. Browser permissions do not encrypt the database; [storage ownership/backups](DATA_STORAGE.md) still apply. See [deployment usage](DEPLOYMENT.md) for Compose, ports, HTTPS and backups; [deployment evidence](DEPLOYMENT_VERIFICATION.md) separates automated checks from pending hardware gates.
