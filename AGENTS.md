# Coding-agent instructions

- Use [DEVELOPMENT.md](docs/DEVELOPMENT.md) as the shared architecture, contract and testing reference. Read the relevant [storage](docs/DATA_STORAGE.md), [API](docs/ADMINISTRATION.md) or [release](docs/RELEASING.md) guide before changing those areas. Keep technical knowledge there; do not add agent-only notes, session diaries or implementation plans.
- Preserve history-before-matching, exact vendor-neutral event semantics, bounded resources, revision checks before dispatch and cleanup-before-worker-replacement. Do not introduce a framework or dependency without a concrete need. Check version-matched SharpOnvifClient APIs rather than assuming upstream main matches the pinned package.
- Let TaskFlow own scheduling, capacity and lifetime; do not duplicate its queues or active sets. Keep admission synchronous, observe every accepted completion, and settle the original flow before disposing dependencies. A cancelled hosted stop only ends the host's wait; see [dispatch lifetime and testing](docs/DEVELOPMENT.md#http-delivery-and-diagnostics).
- Never commit real credentials, destination tokens/URLs, private addresses, device identities, databases, `.env` or unsanitized captures. Use synthetic fixtures and ignored local configuration. Do not log URLs, headers, bodies, passwords or arbitrary exception text; preserve seeded-secret redaction coverage.
- Keep administration authenticated, mutation origin/CSRF checks, safe text rendering, masked reads and commit-before-activation. Storage permissions are not encryption. Never add a global TLS bypass.
- Follow `.editorconfig` for C#. Before committing C# changes, run `dotnet format whitespace OnvifWebhookBridge.slnx`, then the same command with `--verify-no-changes`.
- Run a Release build with analyzers and the relevant [validation](docs/DEVELOPMENT.md#validation); report commands, results and checks not run. Do not weaken tests to hide failures or describe simulation/emulation as hardware interoperability. Documentation-only changes need command/link review, not artificial implementation tests.
- Preserve unrelated user changes and the license. Commit only when requested. Pushing, merging, tagging, publishing images/releases and deploying require explicit user/session authorization; a successful test run grants none of these.
- Manual webhook tests cause real actions. Use local recorders unless the actual destination/action is explicitly authorized. Coordinate device restarts; do not change firmware, detection settings, video/PTZ or destination-host settings incidentally.
